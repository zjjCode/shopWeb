## 一、缺口 #1：售后期字段写入 —— ✅ 已闭环（无需改代码）

### 结论
`orders.after_sale_expire_at` **已由业务代码正确写入**，与 backlog「业务代码从未写入」的描述**不符**。该字段在订单进入 `COMPLETED` 时经状态机的 `extraData` 落库，无需补代码，仅需本文档说明。

### 证据链（file:line）
1. **`server/src/services/OrderService.ts`**
   - `confirmReceipt`（L585 注释 + L608 计算 + L619 透传）：
     ```ts
     const afterSaleExpireAt = new Date(completedAt.getTime() + AFTER_SALE_DAYS * DAY_MS); // L608
     // ...
     transition(tx, { ..., extraData: { completedAt, afterSaleExpireAt } }); // L619
     ```
   - `autoConfirm`（L659 计算 + L671 透传）：同样计算 `afterSaleExpireAt = completedAt + 7 天` 并经 `extraData` 透传。
   - `AFTER_SALE_DAYS = 7`（L198，与 `docs`/配置 `SHOP__ORDER__AFTER_SALE_DAYS` 口径一致）。
2. **`server/src/services/OrderStateMachine.ts`**
   - `transition()`（L112-115）：
     ```ts
     const updated = await tx.order.updateMany({
       where: { orderNo: input.orderNo, status: input.fromStatus },
       data: { status: input.toStatus, ...(input.extraData ?? {}) }, // L114：extraData 被 spread 进 orders 更新
     });
     ```
   - `extraData` 类型为 `Prisma.OrderUpdateManyMutationInput`（L88），`afterSaleExpireAt` 作为 `orders.after_sale_expire_at` 的列名映射由 Prisma 自动完成。
3. **测试实证**：`server/src/tests/unit/orderShip.spec.ts`
   - L161 `it('SHIPPED → COMPLETED：条件更新 + completedAt + afterSaleExpireAt(7d) + emit order.completed')`
   - L179 `expect(upd.data.afterSaleExpireAt).toBeInstanceOf(Date);`
   - L182 断言 `afterSaleExpireAt - completedAt === 7 天`。

### 影响
- 原 backlog「售后期字段未写入」条目作废；不应再据此派工改代码，否则会与既有逻辑重复。
- 若需扩展售后期规则（如不同类目不同天数），改 `OrderService` 的 `AFTER_SALE_DAYS` 取值即可，状态机无需动。

## 二、前端门禁（Task #31）—— 以 `tsc` 为约定，消除 broken promise

### 决策
用户给出二选一（补 eslint / 以 tsc 为约定）。本阶段选择 **以 `tsc`（具体为 `vue-tsc --noEmit`）为前端门禁**，理由：
1. `web/package.json` 原 `lint`/`format` 脚本引用 `eslint`/`prettier`，但 **`web` 的 `devDependencies` 未声明二者** —— 属于 broken promise，`npm run lint` 直接报「eslint 未找到」。
2. `web` 已声明 `vue-tsc@^2.0.26`，`typecheck` 脚本真实可用；实测 `cd web && npx vue-tsc --noEmit` **退出码 0（0 错误）**，门禁当下即有效。
3. 补 eslint 需新增依赖 + 配置 + 网络安装，风险与收益不成正比；类型检查是前端最实质的静态保障。

### 落地改动（`web/package.json`）
```diff
- "lint":     "eslint \"src/**/*.{ts,vue}\" --ext .ts,.vue",
- "lint:fix": "eslint \"src/**/*.{ts,vue}\" --ext .ts,.vue --fix",
- "format":   "prettier --write \"src/**/*.{ts,vue,scss}\"",
+ "lint":     "vue-tsc --noEmit",
+ "lint:fix": "vue-tsc --noEmit",
+ "format":   "echo 'Prettier 未在本阶段接入；前端门禁以 vue-tsc 类型检查为准（npm run lint）。'",
```
- `lint` 现在真实执行类型检查（`vue-tsc --noEmit`），与 `typecheck` 同义但语义更贴近「门禁」。
- `lint:fix` 指向同一命令（类型错误无自动修复，故不伪装 `--fix`）。
- `format` 改为说明性 echo，彻底移除对未安装 prettier 的引用。

### 约定（团队铁律）
- **前端门禁 = `npm run lint`（= `vue-tsc --noEmit`）**。提交前须 `cd web && npm run lint` 归零。
- `web` 的 `build` 脚本（`vue-tsc --noEmit && vite build`）已内置同一检查，CI 可直接复用。
- 若后续接入 Prettier/ESLint，应将 `lint` 升级为「类型检查 + lint」组合，而非回退到仅 lint。
